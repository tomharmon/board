## Actual differences

The [native/browser visual audit](INSPECTOR-VISUALS.md) covers the shell, task
board and settings. Additional real-window regressions exercise
[scoped unread positions and draft visibility](../ui/tests/inspector/sidebar.rs),
[delayed file chooser results across editors](../ui/tests/inspector/picker.rs)
and [an exact guarded reply inside a selected task](../ui/tests/inspector/task_conversation.rs).

Additional parity verified directly against the composer, attachment rows, scheduled replies and message delivery details:

- The native inspector implements a resizable sidebar and thread split, a compact drawer, light/dark palettes and a chronological home timeline. See the [measured visual comparison](INSPECTOR-VISUALS.md). The channel feed and home timeline initially load 50 rows. Scrolling to the first row prepends another 50 and anchors the row on screen, up to a 200-row window; the paging buttons traverse arbitrarily long histories beyond it. `scrolling_to_the_oldest_loaded_row_prepends_history_without_losing_the_reading_position` checks the actual native wheel event, retained rows and anchor bounds. Unlike the browser, the native inspector does not accumulate unbounded history, encode browser URLs or attempt optimistic remote delivery. It polls local commits roughly once per second. Per-channel read marks and the history's board-wide checkpoint are separate SQLite preferences.
- One shared filter applies to channel thread summaries and individual Home/Activity messages, while the event log/unread checkpoint remains unfiltered. Filters are not serialized in a bookmark. Label suggestions come from loaded visible rows, not an exhaustive database-wide index. Dates and gutter times use UTC rather than the browser's local timezone. The new-message jump applies to live pages; an explicitly paged thread has a separate **Latest** action. At a full window the oldest rows can roll out of the live page; they remain accessible through older pages.
- Video opens explicitly rather than embedding browser controls in each row. Its preview downscales, samples frames, and downmixes sound instead of playing at native resolution/frame rate with surround audio. Only the codecs and local tools [documented here](../ui/README.md) are supported. PNG/JPEG, bounded GIF/WebP animations and AVIF stills can be previewed; GIF/WebP files exceeding the 24 MiB or 128-frame animation budget show their first frame, and AVIF requires the optional local decoder. SVG, PDF and audio-only attachments can be saved, just as in the reference. No remote avatar retrieval or automatic URL opener. Large resumable uploads and staged-asset reuse are not composer controls. A PNG clipboard image is supported; arbitrary clipboard HTML is not inserted as markup.
- Scheduling accepts timezone-qualified text rather than a graphical calendar. A top-level task's full routing form offers explicit ID/name fields rather than a graphical dependency picker. A naked `@` does not enumerate the directory; enter part of a name or open the explicit mention picker. On another profile or credential, drafts are distinct rather than shared via browser session storage.
- **Settings > Sync** creates and configures GitHub, Slack, Linear and local mappings. It can copy a command targeting the open database, but does not itself perform a remote pull or publish. Uncertain-delivery reconciliation, issuing credentials and consuming or acknowledging watcher deliveries still use the CLI/API. A local receipt view is not independent proof that a provider accepted a delivery.

Run `cargo test --locked --offline -p board-ui` after fetching dependencies. Headless operation needs a working local graphics driver (hardware or software), not a display server, provider account, HTTP service or worker. [Inspector instructions](../ui/README.md) include a reproducible PNG and element-tree command.
